# Boccia Strategy Board（ボッチャ戦術分析ボード）

Webブラウザで動くボッチャの盤面再現・暫定得点・戦術検討アプリです。iPad Safari のタッチ操作を最優先に設計しています。

> **規則の版と限界**
> 『日本ボッチャ協会競技規則 2021–2024 v.2.0』（通常版）と『日本ボッチャ協会競技規則 フレンドリーマッチ版 v.2.0』に基づく**トレーニングツール**です。最新の公式規則への準拠や審判判定の代替は保証しません。大会固有の申し合わせや審判の判断が優先されます。

---

## インストールと起動（Windows）

Node.js 18 以上（推奨 20 以上）が必要です。

```bash
npm install
```

```bash
npm run dev
```

ブラウザで http://localhost:5173 を開きます。

その他のコマンド：

| コマンド | 内容 |
|---|---|
| `npm run build` | 型チェック＋本番ビルド（`dist/`。PWA用 Service Worker も生成） |
| `npm run preview` | ビルド結果をローカル配信（PWA・オフライン動作の確認用） |
| `npm test` | ユニットテスト（Vitest：幾何・得点・規則・試合進行・JSON検証） |
| `npm run test:e2e` | 画面操作テスト（Playwright：iPad横向きWebKit・縦向きChromium、タッチ操作） |

初回のみ、E2Eテスト用ブラウザを入れてください：`npx playwright install chromium webkit`

### iPad から接続する（同じLAN）

1. PC で `npm run dev` を実行します（`--host` 付きで起動するため、LAN からアクセスできます）。
2. 表示される `Network: http://192.168.x.x:5173/` のURLを iPad の Safari で開きます。
3. つながらない場合は、Windows Defender ファイアウォールで Node.js の「プライベートネットワーク」通信を許可してください。

**ホーム画面に追加・オフライン利用**：Service Worker は `localhost` か HTTPS でのみ動きます。LAN の http 接続では通常のWebページとして動き、オフライン起動はできません。オフラインで使うには `npm run build` で作った `dist/` を HTTPS で配信します（例：GitHub Pages や Netlify などの静的ホスティング）。そのURLを Safari で開き、共有メニューの「ホーム画面に追加」を選びます。一度開けば、通信なしでも起動し、保存済みの盤面を閲覧・編集できます。

## 使い方

### 画面構成
- **上部**：盤面名（タップで名前変更）／自由配置・試合再現の切替／通常版・フレンドリー版の切替／保存一覧・書出・共有・ヘルプ
- **ツール**：選択・移動、白（ジャック）、赤、青、削除、矢印、目標点、計測、注釈
- **中央**：実寸のコート（右下で拡大・縮小・ジャック周辺・全体表示）
- **情報パネル**（iPad横向きは右側、縦向きは下側で折りたたみ可）：盤面／球／作戦／局面／試合／設定
- **下部**：戻す・やり直す、1投記録（試合中）、局面を保存、比較、全体表示、初期化

### 基本操作
- 球の色を選んでコートを**タップすると1球追加**します。球を**ドラッグすると移動**します（球ツールのままでも、球の上から指を動かせば移動）。
- **2本指でピンチズーム・パン**、余白を1本指でドラッグしてパン。ページ全体はスクロールしません。
- 球を選ぶと「球」タブで **x・y座標（cm）を数値入力**でき、**1cm／5cm単位の移動ボタン**も使えます。タッチしにくい球は一覧から選べます。
- 追加・移動・削除・状態変更はすべて**戻す／やり直す**の対象です。削除と初期化の前には確認を出します。
- キーボード：Ctrl+Z／Ctrl+Shift+Z（Ctrl+Y）、Delete、矢印キー（1cm、Shift で5cm）、V/J/R/B/M/A/T でツール切替、Esc で選択解除。

### 自由配置モード（初期表示）
- 投球順を強制せずにジャック・赤・青を配置します。7球目以降を追加すると「非公式の自由配置」と表示します。
- 配置を変えるたびに距離順位と**暫定得点（このまま終了した場合）**を再計算し、得点の根拠（得点球と距離）を一覧で示します。
- 「局面」タブで**分岐（A案→B案）・局面の保存・A/B比較**（暫定得点、ジャックの移動距離、未配置球、接触候補、重なり）ができます。
- 「作戦」タブで目標点・矢印・注釈を作図します。戦術タグ（近づける／相手球を押す／ジャックを動かす／ブロックする）や戦術メモ（狙い・成功時の配置・失敗時のリスク・相手の残り球）を付けられます。

### 試合再現モード
1. 「試合再現」→ 規則版・試合形式（個人／ペア／チーム）・競技クラス・エンド数・持ち時間・選手名を設定します。
2. **ジャック投球**：担当ボックスが表示されます。ジャックを置いて「有効」か「ファウル」を記録します。
3. **カラー球**：次に投げるサイドと、その根拠になる条文が表示されます。球を置き、当たって動いた球も置き直してから「**この状態を1投として記録**」を押します（結果：有効／アウト／反則除去、エリア外の球のアウト化、ジャックのクロス再配置、所要時間、メモ）。**ドラッグしただけでは球数も持ち時間も減りません。**
4. 両サイドが投げ終わる（またはBNP申告）と採点画面になります。手動での得点修正（理由付き）、ペナルティボール（通常版のみ）を入れて「エンド得点を確定」します。
5. 規定エンド終了時に同点なら、通常版は**追加エンド**、フレンドリー版は**ファイナルショット**を行います。
6. 投球履歴は任意の時点を表示でき、「ここから分岐」で自由配置の新しい盤面になります（元の試合は消えません）。

### 保存・書き出し
- 操作のたびに端末内（IndexedDB）へ**自動保存**され、リロードしても続きから再開できます。データを外部へ送信することはありません。
- 「保存一覧」で開く・複製・名前変更・削除・検索ができます。
- 「書出・共有」から次の形式で書き出せます。
  - **PNG・SVG**：盤面の画像。タイトル・得点・球番号・寸法・作図・距離線を表示するか選べます。
  - **JSON**：書き出しと読み込みの両方に対応。読み込み時に形式・座標範囲・ID重複・版番号を検証します。
- iPad では共有シートを使い、使えないブラウザではダウンロードします。

## 未実装・制限事項

- **簡易2D投球シミュレーション**（任意機能）は実装していません。投球結果は手作業で置き直す方式です。
- 物理挙動（速度・摩擦・跳ね返り・球の変形）、画像認識、AIによる最善手、オンライン対戦は対象外です。
- 接触候補は直線経路上の幾何判定だけです。上から越える投球・曲がり・弾きは計算しません。
- ディスラプティッドエンド（通常版 §12）、イエロー／レッドカード、ドロップボール、メディカル／テクニカルタイムアウトの専用フローはありません。必要に応じて投球記録のメモ・手動判断で記録してください。
- ペナルティボールは付与と結果をユーザーが確定する方式です。反則の判定やターゲットボックス内かどうかの判定は自動化していません。
- タイマーは手動操作の補助で、審判用の公式時計ではありません。
- 実機確認は Playwright の iPad 相当環境（WebKit・タッチ）で行いました。実機の iPad Safari では未確認です。

## 規則の根拠と、このアプリでの解釈

### 座標系とコート（通常版 §3.1・p.35–36／フレンドリー版 p.13–14）
- 原点 `(0,0)` はコートの上端左隅（投球エリアと反対側）です。右が +x、下が +y、単位は m です。
- 寸法：コート 6.00×12.50m、プレイングエリア 10.00m、スローイングライン y=10.00、ボックスは横1m×6、クロス (3.00, 5.00)、Vライン (0,7.00)→(3.00,8.50)→(6.00,7.00)。
- 外枠は内側の縁を基準に計測します。スローイングラインとVラインのテープはジャック無効エリア側に貼られ、10mライン・Vラインの寸法は有効側の縁までです（通常版 p.36）。そこで**判定は有効側（内側）の縁**で行い、線幅は描画にだけ使います。
- 外周ラインに接触・越えた球はアウトです（通常版 §10.10.1）。円が縁に触れた時点でエリア外とし、中心点だけでは判定しません。
- ジャックは「Vラインを完全に越えなければ有効とならない」（両版 §1 用語の定義）ため、円全体が有効側にある場合だけ有効とします。

### 球と距離（通常版 §5・§10.16／フレンドリー版 §5.1・§8.14）
- 半径は公称円周270mmから算出した ≒4.297cm で、描画と簡易測定のための近似値です。
- 順位は表面間の推定距離（中心間距離 − ジャック半径 − 球半径）で決めます。全球が同じ半径なら、中心間距離の順位と一致します。
- 座標上の同距離は、丸め誤差（1nm）だけを吸収して等距離とします。差が1mm未満のときは「近接・要計測」と警告し、公式の同距離とは断定しません。審判判断による補正（同距離／赤優勢／青優勢）ができます。

### 規則版の違い

| 項目 | 通常版 | フレンドリー版 |
|---|---|---|
| ボックス・球数 | 個人 赤3青4・6球／ペア 赤2,4 青3,5・1人3球／チーム 赤1,3,5 青2,4,6・1人2球（§2） | 同じ（§2, §5） |
| エンド数 | 個人・ペア4、チーム6（§2） | 本文に明示なし → 同じ値を「通常版からの初期提案／大会要確認」と表示 |
| 持ち時間 | BC1 5分、BC2 4分、BC3 6分、BC4 4分、OP座位・立位 4分、チーム6分、BC3ペア7分、BC4ペア5分（§10.2.1） | 個人4分、ペア・チーム5分（§8.2.1。主催者が変更でき、編集可） |
| ジャック担当 | 個人は赤青交互、ペア2→5番、チーム1→6番（§2） | 第1エンドは赤（§8.3.1）。以降の順は「初期提案／大会要確認」 |
| ジャックファウル | 次エンドの担当。最終エンドは第1エンドの担当。有効になるまで繰り返す（§10.4.2） | 次エンドの担当（§8.4.2）。最終エンド・連続ファウルは**手動判断** |
| 等距離・同得点 | 最後に投球した側、以後交互（§10.13） | 同じ（§8.12） |
| 等距離・得点球数が異なる | 得点球の少ない側（§10.13） | 本文に明示なし → **主催者・審判判断** |
| ジャックのクロス再配置 | クロスに球があれば前面中央のできるだけ近く（§10.11.2）。カラー球がなければ弾き出した側が投球（§10.11.4） | クロスへ戻す（§8.11.1）。塞がっている場合とカラー球がない場合は**手動判断** |
| タイブレイク | 追加エンド。同点なら前回後攻側のジャックで繰り返す（§13）。得点は合計に加算しない | ファイナルショット：各サイド1球・1分以内（§10）。加算しない。同点時の規定はなく、主催者判断 |
| ペナルティボール | あり：35cmターゲットボックス、1球1点（§15.2, §10.16.3） | 加点フローなし。反則はボール除去（§11） |

コード上では、規則の違いを `src/domain/rules/standard-v2.ts` と `friendly-v2.ts` に分けています。UIは規則版ごとに分岐せず、`RuleProfile` を通して扱います。

## コード構成

```text
src/
  app/                 画面レイアウト（Header, Toolbar, BottomBar, App）
  components/court/    CourtView（操作）, CourtContent（描画）, exportBoard（PNG/SVG）
  components/panels/   盤面・球・作戦・局面・試合・設定パネル
  components/dialogs/  試合設定、1投記録、書き出し、保存一覧、A/B比較、ヘルプ
  domain/              純粋関数（React非依存）
    geometry.ts        コート定数、距離、Vライン・エリア判定、重なり、接触候補、ジャック再配置
    scoring.ts         有効球抽出、距離順位、暫定得点、近接警告、手動補正
    turn-engine.ts     次投球サイド判定
    match.ts           試合再現の状態遷移（ジャック／投球／BNP／採点／タイブレイク）
    document.ts        保存データの型と生成
    rules/             standard-v2.ts, friendly-v2.ts, registry.ts, profile.ts
  store/               Zustand ストア（スナップショット方式の Undo/Redo）、自動保存、タイマー
  persistence/         IndexedDB、JSON検証（zod）と版移行
  tests/               Vitest ユニットテスト
e2e/                   Playwright 画面操作テスト
```

保存データには原本値（座標・状態・履歴・手動補正）だけを入れます。距離や暫定得点などの派生値は表示のたびに計算し、保存しません。
